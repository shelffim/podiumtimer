# UX 가이드

사용자가 Podium Timer를 처음 알게 된 순간부터 첫 리허설, 공유, 결제, 재방문까지 각 단계에서 무엇을 보고 어떻게 다음 단계로 넘어가는지 정한다. 범위·정책은 `docs/PRD.md`, 생김새(색·컴포넌트·크기)는 `docs/DESIGN.md`가 기준이다. 이 문서는 그 둘 사이의 **흐름**을 다룬다. 서로 부딪치면 PRD → DESIGN → 이 문서 순서로 따른다.

원칙은 Figma의 [UI 디자인 원칙](https://www.figma.com/ko-kr/resource-library/ui-design-principles/) 7가지(계층 구조·점진적 공개·일관성·대비·접근성·근접성·정렬)를 이 앱에 맞게 옮겼다.

## 핵심 규칙
1. **화면마다 다음 단계는 하나다.** 흰 Primary 버튼 하나로 보인다. 다른 길은 Secondary나 글자 버튼이다.
2. **첫 판정까지 가는 길에 단계를 더하지 않는다.** 랜딩에서 처음 "0:12 늦음"을 보기까지가 이 앱의 진입 비용이다.
3. **기능은 필요한 순간에 하나씩 보인다.** 공유는 시작 전, 평균은 기록 2개부터, 결제 안내는 한도에 닿은 순간에만.
4. **막다른 화면을 만들지 않는다.** 빈 상태·에러·한도·끝 화면마다 다음에 할 일을 준다.
5. **시청자 화면이 가장 많은 사람이 보는 첫인상이다.** 발표자 한 명이 시청자를 최대 9명 데려온다.

## 1. 단계 사다리

| 단계 | 사용자 속마음 | 화면 | 넘어갔다는 신호 | 다음으로 미는 장치 |
|---|---|---|---|---|
| 0 알게 됨 | "이게 뭐지?" | 단톡방 링크 미리보기, 시청자 화면 | 랜딩 방문 | 링크 미리보기 문구, 위쪽 바의 `Podium Timer` |
| 1 이해 | "나한테 필요한가?" | 랜딩 | [Google로 시작하기] | 헤드라인, 늦음 판정이 보이는 미리보기 |
| 2 가입 | "번거롭지 않나?" | Google 로그인 | 내 타이머 목록 도착 | 추가 입력 없음 |
| 3 첫 타이머 | "어떻게 나누지?" | 빈 목록 → 만들기 | [저장] | 예시 문구, 빈 줄 하나로 시작 |
| **4 첫 판정** | "정말 알려주나?" | 저장 카드 → 시작 전 → 진행 | 첫 [다음]에서 직전 구간 판정을 봄 | [▶ 바로 리허설 해보기], 조작 안내 |
| 5 반복 | "어디가 문제지?" | 결과 → 다시 하기 → 기록 | 기록 2개, 평균을 봄 | [다시 하기], 평균 예고 문구 |
| 6 공유 | "다 같이 볼 수 있나?" | 시작 전 공유 카드 → 시청자 화면 | 시청자 입장 | [복사], 접속 칩 |
| 7 결제 | "돈 낼 만한가?" | 한도 안내 → 요금제 → 결제 확인 | 30일권 반영 후 원래 화면 | 막힌 자리의 안내, `returnTo` |
| 8 재방문 | "어디까지 했지?" | 목록·기록 | 다시 [시작] | 목록 카드의 [▶ 시작] |

**핵심 경험은 4단계다.** 처음으로 자기 발표의 "0:12 늦음"을 보는 순간, 남은 시간만 보여주는 타이머와 무엇이 다른지가 처음 보인다. 1~3단계는 이 순간까지 가는 비용이라 줄일수록 좋다.

### 첫 판정까지의 경로
```
랜딩 [Google로 시작하기] → Google 계정 선택 → 빈 목록 [첫 타이머 만들기]
  → 이름·구간 입력 → [저장] → [▶ 바로 리허설 해보기] → [시작] → (말하고) 화면 탭 → 첫 판정
```
- 지금은 탭 6번과 입력이다. 이 경로에 화면·모달·질문을 더하지 않는다. 온보딩 슬라이드, 튜토리얼 오버레이, 가입 설문, 프로필·닉네임 설정, 알림 권한 요청은 만들지 않는다.
- 경로 위의 화면은 다음 단계 버튼이 Primary 하나다. 갈림길([목록으로], [공유 링크 만들기])은 Secondary다.
- 구간 1개, 이름 하나만 있어도 저장하고 시작할 수 있다. "제대로 만들어야 시작할 수 있다"는 인상을 주지 않는다.

## 2. 7가지 원칙을 이 앱 규칙으로

### 2.1 계층 구조 — 화면마다 주인공 하나
먼저 볼 것, 다음에 볼 것, 스크롤해야 보여도 되는 것을 정해 두고 크기·굵기·밝기를 그 순서에 맞춘다.

| 화면 | 1순위 | 2순위 | 3순위 |
|---|---|---|---|
| 랜딩 | 헤드라인 | [Google로 시작하기] (끝 띠에 같은 버튼 한 번 더) | 재생되는 미리보기, 비교 그림, 기능 카드 3개 |
| 타이머 목록 | 타이머 이름 + [▶ 시작] | [+ 새 타이머 2/3] | 플랜 칩, 30일권 구매 |
| 편집 | 구간 줄(이름·시간) | [저장] | 개수·합계, 한도 안내, 삭제 |
| 시작 전 | [▶ 시작] | 구간 개요(개수·합계·타임라인) | 공유 카드 |
| 진행 | 현재 구간 남은 시간 | 직전 구간 판정 | 구간 이름·다음 구간, 타임라인, 전체 남은 시간 |
| 결과 | 결과 표의 차이 칸 | [다시 하기] | [기록 보기], [구간 고치기] |
| 기록 | 평균 막대그래프 | 기록 카드 | 펼친 표, 삭제 |
| 시청자 입장 | 타이머 이름 | 닉네임 칸 + [입장] | 안내 캡션 |
| 요금제 | 30일권 카드 | [30일권 구매 $3.99] | 연장·환불 안내 |

- 위계는 크기·굵기·밝기로만 만든다. 빨강·파랑은 위계 수단이 아니다(DESIGN 원칙 2).
- Primary(흰 알약)는 "이 화면의 다음 단계"다. 한 화면에 Primary가 여러 개 보이는 경우는 같은 카드가 반복될 때(목록의 [▶ 시작])뿐이다.
- 1순위와 Primary는 폰 첫 화면에서 스크롤 없이 보여야 한다.

### 2.2 점진적 공개 — 필요한 순간에 하나씩

| 기능 | 보이기 시작하는 순간 | 그 전에는 |
|---|---|---|
| 공유 | 시작 전 화면 | 랜딩 기능 소개 한 줄 |
| 평균 | 같은 구간 구성의 기록 2개 | 첫 기록의 결과 화면에 "한 번 더 하면 구간별 평균을 볼 수 있어요", 기록 화면에 "기록이 2개 이상 쌓이면 구간별 평균을 보여줘요" 한 줄 |
| 30일권 안내 | 타이머 4개째, 구간 11개째, 자리 가득 | 목록 위쪽 바의 [30일권 구매] 글자 버튼, 새 타이머 버튼의 `2/3` |
| 종료 확인 | 마지막 구간의 첫 [다음] | 없음 |
| 기록의 결과 표 | 기록 카드를 펼칠 때(한 번에 하나) | 요약 한 줄 |
| 조작 안내 | 시작 전 [시작] 아래 캡션, 진행 중 아래쪽 한 줄 | — |

- 진행 정도는 숫자로 보여준다: `3 / 7`, `6 / 10개`, `2/3`, `접속 2/3명`. 사용자는 지금 어디쯤이고 얼마나 남았는지 늘 안다.
- 한도는 숨기지도 미리 막지도 않는다. 버튼은 늘 누를 수 있고, 누른 순간 같은 자리에 이유와 해결책을 보여준다(PRD 정책).
- 설정·옵션을 늘리지 않는다. 선택지가 필요해 보이면 기본값 하나로 정한다.

### 2.3 일관성 — 같은 일은 같은 이름, 같은 자리

| 동작 | 문구 | 아이콘 | 모양 | 자리 |
|---|---|---|---|---|
| 발표 시작 | 시작 | `play` | Primary | 목록 카드, 시작 전 맨 아래, 기록 위 |
| 다음 구간 | 다음 / 종료(마지막 구간) | `arrow-right` | Primary 큰 버튼(마우스), 화면 탭(터치) | 진행 화면 아래 |
| 되돌리기 | 되돌리기 | `undo` | 원형 아이콘 버튼 | 진행 위쪽 바 오른쪽 |
| 중단 | 중단 | `square` | 원형 아이콘 버튼 + 확인 모달 | 진행 위쪽 바 맨 오른쪽 |
| 같은 타이머 다시 | 다시 하기 | `restart` | Primary | 결과, 중단 화면 |
| 뒤로 | 뒤로 | `arrow-left` | 원형 아이콘 버튼 | 위쪽 바 왼쪽 |
| 결제 안내로 | 30일권 보기 | — | Primary(안내 박스 안) | 한도 안내 박스 |
| 삭제 | ○○ 삭제 | — | 글자 버튼 + 확인 모달 | 화면·카드 맨 아래 |

- 새 화면에서 위 표에 있는 동작을 쓰면 같은 문구·아이콘·자리를 쓴다. 표에 없는 동작이 생기면 이 표에 먼저 한 줄 더한다.
- 확인은 모두 `ConfirmDialog`, 한도·인원 안내는 모두 `LimitNotice`다. 같은 역할에 다른 모양을 만들지 않는다.
- 시청자 진행 화면은 발표자 진행 화면에서 조작만 뺀 것이다. 숫자 위치·크기·판정 표기가 같아야 발표자와 시청자가 같은 화면을 보며 말할 수 있다.

### 2.4 대비 — 색 대신 밝기로 강약을 준다
Figma 예시는 위험한 동작을 빨강으로 강조하지만, 이 앱에서 빨강은 "늦음"이다. 강약은 밝기로만 준다.

| 강도 | 모양 | 쓰는 곳 |
|---|---|---|
| 강함 | 흰 바탕 검은 글자(`btn-primary`) | 다음 단계 |
| 중간 | `card` 바탕 흰 글자(`btn-secondary`) | 다른 길(편집, 기록, 공유 링크 만들기) |
| 약함 | 배경 없는 `soft` 글자(`btn-text`) | 드물거나 되돌리기 어려운 일(삭제, 위쪽 바의 30일권 구매) |

- 위험한 동작은 약하게, 멀리(2.6), 확인 한 번 더로 다룬다.
- 진행 화면에서 가장 밝고 큰 것은 남은 시간 숫자 하나다.

### 2.5 접근성
토큰별 글자 대비(WCAG 대비율, 계산값):

| 글자 \ 배경 | `surface` | `card` | `fill` |
|---|---|---|---|
| 흰색 | 19.7 | 17.8 | 15.9 |
| `soft` | 8.6 | 7.8 | 7.0 |
| `muted` | 5.1 | 4.6 | **4.1** |
| `red-400` (늦음) | 6.8 | 6.1 | 5.5 |
| `blue-400` (빠름) | 7.5 | 6.7 | 6.0 |
| `neutral-300` (정시) | 13.3 | 12.0 | 10.8 |

- 본문 기준(AA 4.5:1)을 모두 넘는다. 단 `muted`는 `fill` 위에서 4.1이라 그 위에 글자로 쓰지 않는다(비활성 아이콘은 예외).
- 타임라인 블록(남은 구간 `line` 1.4, 끝난 구간 2.4)은 그래픽 기준 3:1에 못 미친다. 진행은 `3 / 7`과 전체 남은 시간 글자로도 알 수 있으므로 보조 표시로만 쓴다. 타임라인만으로 전하는 정보를 만들지 않는다.
- 빨강(`red-400`)과 파랑(`blue-400`)은 밝기가 거의 같아(OKLCH 명도 70.4%·70.7%) 흑백이나 색각 이상에서는 구분되지 않는다. 판정에 "늦음·빠름·정시" 글자를 붙이는 것은 장식이 아니라 필수다.
- 남은 시간 숫자는 360px 폰에서 약 108px(`30vw`)이다. 단상 1m 거리 가독성을 위해 이보다 작게 만들지 않는다.
- 매초 바뀌는 숫자에 `aria-live`를 달지 않는다. 화면 읽기가 1초마다 끼어든다.
- 키보드만으로 전체 흐름이 된다: Tab으로 [시작], `Space`로 다음, 손잡이에서 ↑/↓로 구간 순서, `Esc`로 모달 닫기.
- 터치 대상 44px, 포커스 링, 아이콘 버튼의 `aria-label`·`title`, `prefers-reduced-motion`은 DESIGN.md를 따른다.

### 2.6 근접성 — 묶을 건 묶고, 위험한 건 떼어 놓는다
- **진행 화면**: [되돌리기]·[중단]은 진행 칩과 같은 위쪽 바에 두고, 그 아래 전체가 "다음" 탭 영역이다. 경계선으로 두 영역을 나눈다. 손이 자주 닿는 가운데·아래에 중단을 두지 않는다.
- **판정 글자**는 그 구간 이름 바로 옆에 붙인다("직전 구간 · 도입 0:12 늦음"). 어느 구간의 결과인지 따로 찾지 않게 한다.
- **편집**: 한 줄이 한 구간이다(`손잡이 | 이름 | 시간 | ✕`). 에러는 그 줄 바로 아래. [타이머 삭제]는 [저장]에서 떨어진 맨 아래.
- **공유 카드**: 링크 상자와 [복사]는 한 줄, 접속 인원과 닉네임 칩은 그 아래 한 덩어리, 자리 가득 안내는 인원 바로 아래.
- **기록**: [이 기록 삭제]는 펼친 결과 표 아래, 그 기록 안에만 둔다.
- 그룹은 간격으로 보여준다. 같은 그룹 안의 간격은 그룹 사이(24px, `md` 32px)보다 좁게 둔다. 카드 하나로 묶이면 선이나 박스를 더하지 않는다.

### 2.7 정렬
- 기준선은 왼쪽 하나다. 타이머 화면의 구간 이름·숫자·판정·타임라인이 같은 왼쪽 선에서 시작한다.
- 표의 숫자는 오른쪽 정렬 + `tabular-nums`. 위아래 줄의 분·초 자리가 맞아 비교가 된다.
- 가운데 정렬은 상태 하나만 보여주는 화면(없는 링크, 인원 가득, 중단, 대기 스피너 카드)과 푸터, 탭 안내 한 줄에만 쓴다.
- 여백·최대 폭은 DESIGN.md 레이아웃을 따른다.

## 3. 단계별 설계

### 3.1 알게 됨 — 공유 링크와 시청자 화면이 광고다
- 교사가 단톡방에 붙인 링크의 미리보기가 학생들의 첫인상이다. 페이지 메타데이터에 서비스 이름과 한 줄 설명을 둔다(6절 1번).
- 시청자 화면은 발표자 화면과 같은 `TimerFace`로 같은 품질을 보여준다. 대기실·결과 화면 위쪽 바의 `Podium Timer`는 랜딩으로 가는 링크이고, 지금은 이것이 시청자가 발표자가 되는 유일한 길이다.
- 시청자 화면에 가입 유도·팝업·광고 문구를 넣지 않는다(시청자 결과 화면의 "나도 만들기"는 PRD 제외 사항, 7절).

### 3.2 이해 → 가입 (랜딩)
- 첫 화면에서 세 질문에 답한다: 무엇인가(헤드라인), 어떻게 보이나(미리보기에서 [다음]을 누르는 순간 배지가 "0:04 빠름"에서 "0:12 늦음"으로 바뀌는 장면), 무엇이 드나(무료, Google 계정 하나).
- 행동은 로그인 하나다. [Google로 시작하기]는 스크롤 없이 보이고, 페이지 끝 띠에 같은 버튼을 한 번 더 둔다. 다 읽은 사람이 위로 돌아가지 않아도 된다.
- 미리보기는 실제 진행 화면과 같은 모양이다. 가입 뒤 보는 화면이 미리보기와 같아야 기대가 맞는다. 마우스 기기는 [다음]·Space로, 터치 기기는 화면 탭으로 넘기는 모습을 보여준다(진행 화면과 같은 기준).
- 미리보기는 스스로 재생되고 방문자가 조작하지 않는다(직접 누르는 데모는 8절, PRD 제외 사항). 움직임을 줄인 기기와 첫 그림은 정지 장면이고, 정지 장면에도 늦음 판정이 보인다.
- 스크롤하면 "남은 시간만 보는 타이머와 무엇이 다른가"(비교 그림)와 기능 3개를 그림으로 보여준다. 그림은 실제 화면 모양과 예시 데이터로 그린다.
- 로그인이 실패하면 버튼 바로 아래에 이유를 보이고, 버튼은 다시 누를 수 있다.
- 이미 로그인한 사람은 랜딩을 거치지 않고 목록으로 간다.
- 하지 않는 것: 가격표, 후기, 실적 숫자, 스크롤 애니메이션, 로그인 말고 다른 행동 버튼, 사진·일러스트.

### 3.3 첫 타이머 (빈 목록 → 편집)
- 빈 목록은 카드 하나다: "첫 타이머를 만들어 보세요", 예시("찬성 입론 3:00"), [첫 타이머 만들기]. 다른 버튼은 두지 않는다.
- 편집은 빈 구간 줄 하나로 시작한다. 입력 칸의 예시 글자가 형식을 알려준다(이름 예시, `3:00`). 숫자만 적어도 분으로 읽고(`3` → `3:00`) 칸을 나가면 `m:ss`로 보여준다. 폰에서 `:`를 치려고 자판을 바꾸지 않아도 된다.
- 에러는 [저장]을 누른 뒤 그 줄 아래에 보여주고, 다시 입력하기 시작하면 지운다. 입력 중에 빨강을 띄우지 않는다.
- 개수·합계(`6 / 10개 · 합계 14:00`)가 입력할 때마다 바뀐다. 발표 길이를 맞추는 피드백이다.
- 저장하면 [저장] 자리에 "저장했어요" + [▶ 바로 리허설 해보기](Primary) + [목록으로]. 저장 다음 단계는 리허설이다.

### 3.4 첫 판정 (시작 전 → 진행) — 핵심 경험
- 시작 전 화면은 확인하고 누르는 화면이다: 구간 개요, (선택) 공유, [▶ 시작]. [시작]은 화면 아래에 붙어 있어 구간이 많아도 첫 화면에 보인다. [시작] 아래 캡션이 진행 중 조작(Space·화면 탭)을 미리 알려준다.
- 진행 중 아래쪽 안내("화면 아무 곳이나 탭하면 다음 구간")는 늘 보인다.
- 첫 구간에는 판정 자리에 "첫 구간"을 둬서 자리를 잡아 둔다. [다음]을 누르면 그 자리에 판정이 나온다는 것을 배운다.
- [다음]은 누르는 즉시 숫자·구간 이름·판정이 바뀐다. 서버 응답을 기다리지 않는다. 반응이 늦으면 사람은 두 번 누른다.
- 실수는 [되돌리기] 한 번으로 고친다. 확인 창을 띄우지 않는다.
- 끝은 "한 번 더 누르면 종료"(3초)로 한 번 더 확인한다.

### 3.5 반복 (결과 → 다시 하기 → 평균)
- 결과 화면의 다음 단계는 [다시 하기](Primary, 넓게)다. 리허설은 여러 번 할수록 가치가 쌓인다. 같은 구간 구성의 첫 기록이면 "한 번 더 하면 구간별 평균을 볼 수 있어요"로 다음 리허설의 이유를 준다.
- 결과 표에서 색이 있는 곳은 차이 칸뿐이다. 어디를 고칠지 바로 보인다.
- [구간 고치기]는 "계획이 틀렸다"를 알게 된 사람의 길이다. 고친 뒤에는 저장 카드의 [▶ 바로 리허설 해보기]로 다시 돌아온다.
- 평균은 같은 구간 구성 기록만 넣는다. 캡션 "같은 구간 구성의 기록 N개"로 구간을 바꾸면 평균이 새로 시작된다는 것을 알린다.
- 망친 기록은 지울 수 있다. 평균을 믿을 수 있어야 다시 연습한다.

### 3.6 실전과 공유
- 공유는 시작 전 공유 카드 하나에서 끝난다: [공유 링크 만들기] → 링크 + [복사] → "복사됨" → 접속 인원과 닉네임이 늘어남 → [시작].
- [공유 링크 만들기]는 Secondary다. 혼자 쓰는 사람이 공유를 해야 시작할 수 있다고 느끼지 않게 한다.
- 접속 칩은 발표자가 "다 들어왔나?"를 확인하는 장치이자 [시작] 타이밍의 근거다.
- 진행 중 끊김은 칩 하나("공유 연결 끊김")로만 알린다. 모달·소리 없음. 발표가 먼저다.
- 결과 화면은 "다시 하면 새 공유 링크가 필요해요"를 미리 알려 다음 조를 준비하게 한다.

### 3.7 시청자 (링크 → 입장 → 대기 → 시청 → 결과)
- 입장은 칸 하나와 버튼 하나다. 전에 쓴 닉네임이 채워져 있으면 [입장]만 누른다. "로그인 없이 볼 수 있어요"로 계정 걱정을 없앤다.
- 대기실은 무엇을 기다리는지("발표자가 시작하면 자동으로 시작돼요")와 얼마나 걸릴지(구간 목록·합계)를 보여준다. 시청자는 아무것도 누르지 않아도 된다.
- 막힌 상태(없는 링크·인원 가득·중단)는 가운데 아이콘 + 제목 + 할 일 한 줄이다("자리가 비면 링크를 다시 열어 주세요").
- 시청자 화면에는 탭해도 아무 일이 없으므로 조작 버튼처럼 보이는 것을 두지 않는다.

### 3.8 결제 (한도 → 요금제 → 복귀)
- 결제 안내는 무언가를 하려다 막힌 순간, 그 자리에만 나온다. 무엇이 막혔는지(사실) → 30일권이면 어떻게 되는지(해결) → [30일권 보기] 순서다.
- 결제 이유가 가장 분명한 순간은 자리 가득이다(학생들이 기다리고 있다). 그래서 이 안내는 발표자 시선이 이미 있는 공유 카드의 인원 바로 아래에 둔다.
- 요금제 화면은 무료와 30일권 비교 하나다. 체크 목록은 형용사 없이 한도 숫자로 적는다.
- 결제는 우회로이지 목적지가 아니다. 결제해도, 취소해도 원래 하던 화면으로 돌아간다(`returnTo`).
- 반영 대기는 스피너 + "몇 초면 끝나요". 늦어지면 "결제는 완료됐어요"를 먼저 말해 불안을 없애고 갈 곳([타이머 목록])을 준다.
- 하지 않는 것: 기간 한정·카운트다운, 결제 유도 팝업, 한도 전 버튼 비활성화, 진행 화면의 결제 안내.

### 3.9 재방문과 만료
- 재방문자는 목록 카드에서 바로 [▶ 시작]한다. 요약("6구간 · 합계 10:00")으로 어떤 타이머인지 알아본다.
- 진행 중이던 발표는 다시 열면 그대로 이어진다. "이어서 할까요?"를 묻지 않는다.
- 만료돼도 아무것도 사라지지 않는다. 플랜 칩이 "무료"로 바뀌는 것 말고 경고 화면은 없다.

## 4. 막다른 화면을 만들지 않는다

| 상황 | 화면이 말하는 것 | 다음 할 일 |
|---|---|---|
| 빈 목록 | 첫 타이머를 만들어 보세요 | [첫 타이머 만들기] |
| 구간 0개로 시작 전 | 구간을 추가해야 시작할 수 있어요 | [편집] |
| 기록 없음 | 아직 기록이 없어요 | 위쪽의 [▶ 시작] |
| 기록 1개 | 기록이 2개 이상 쌓이면 구간별 평균을 보여줘요 | 위쪽의 [▶ 시작] |
| 발표 중단 | 발표를 중단했어요 | [다시 하기] |
| 기록 저장 실패 | 기록을 저장하지 못했어요 | [다시 저장] |
| 타이머 없음 | 타이머를 찾을 수 없어요 | [목록으로] |
| 없는 페이지 | 페이지를 찾을 수 없어요 | [처음으로] |
| 앱 오류 | 문제가 생겼어요 | [다시 시도] |
| 한도 도달 | 무료 한도(타이머 3개)에 도달했어요 … | [30일권 보기] |
| 결제 반영 늦음 | 결제는 완료됐어요 | [타이머 목록] |
| 시청자: 없는 링크·인원 가득·중단·결과 | 상태 제목 | 할 일 한 줄(버튼 없음) |

- 새 상태를 만들면 이 표에 한 줄을 더하고 "다음 할 일"을 비워 두지 않는다. 버튼 없이 안내 한 줄로 끝나도 되는 곳은 시청자 화면뿐이다(시청자가 할 수 있는 일은 링크 다시 열기뿐이다).

## 5. 문구
- 버튼은 그 동작의 이름이다: 시작, 다음, 다시 하기, 입장, 저장. 확인 모달의 확인 버튼도 "확인" 대신 "삭제", "중단"처럼 동작 이름을 쓴다.
- 결과는 "~했어요"(저장했어요). 칩·버튼처럼 좁은 곳은 더 짧게("복사됨").
- 막힘은 사실 → 해결 순서로 한 문장씩: "무료 한도(타이머 3개)에 도달했어요. 30일권은 타이머를 제한 없이 만들 수 있어요".
- 숫자는 구체적으로 쓴다. "곧", "많이" 대신 `3/3`, `10명`, "몇 초".
- 사용자를 탓하지 않는다: "입력을 확인해 주세요", "링크 주소를 다시 확인해 주세요".
- 판정 단어는 늦음·빠름·정시 셋뿐이다. "잘했어요", "아쉬워요" 같은 평가를 붙이지 않는다. 빨리 끝난 것이 잘한 것은 아니다.
- 과장·감탄을 쓰지 않는다("최고의", "놀라운", 느낌표).
- 모든 문구는 `src/lib/messages.ts`에 둔다.

## 6. 현재 화면 점검 (2026-10-28 점검 → 2026-10-29 반영)
이 문서 기준으로 코드를 본 결과다. "MVP 안"은 PRD를 바꾸지 않고 고칠 수 있고, "결정 필요"는 PRD·DESIGN을 바꿔야 해서 사용자가 정한다. 2026-10-29에 모두 반영했다(5~7번은 사용자가 고른 안).

| # | 위치 | 점검 때 | 반영 | 구분 |
|---|---|---|---|---|

## 7. 사용성 점검 — 분석 도구 없이
방문자 분석과 측정 데이터는 MVP 제외 사항이다. 대신 사람을 직접 본다.

- 처음 보는 사람 3~5명에게 폰을 주고 설명 없이 과제를 준다. 막혀도 돕지 않고, 멈춘 곳·잘못 누른 곳·한 질문을 적는다.
- 같은 곳에서 두 명 이상 막히면 고친다. 큰 화면 변경 전후로 한 번씩 한다.

| 과제 | 통과 기준 |
|---|---|
| 랜딩을 5초 보고 "이게 뭔지 말해 보세요" | "구간마다 늦었는지 알려준다"에 가까운 말 |
| "3분짜리 발표를 구간 3개로 만들어 리허설해 보세요" | 질문 없이 3분 안에 첫 판정을 본다 |
| 리허설 직후 "어느 구간이 늦었나요?" | 결과 표에서 바로 답한다 |
| (두 명) "친구에게 같은 타이머를 보여 주세요" | 링크 복사부터 시청자 입장까지 질문 없이 |
| "타이머를 4개 만들어 보세요" | 한도 안내를 읽고 무엇을 하면 되는지 말한다 |
| 폰을 1m 떨어진 책상에 두고 진행 화면 읽기 | 남은 시간과 직전 구간 판정을 읽는다 |

## 8. PRD를 바꿔야 하는 제안 — 지금은 만들지 않는다
유입과 단계 전환에 효과가 클 수 있지만 PRD "MVP 제외 사항"에 있어서 이 문서의 규칙이 아니다. 제외를 풀기로 정한 뒤에만 만든다.

| 제안 | 기대 효과 | PRD 제외 항목 |
|---|---|---|
| 시청자 결과 화면의 [나도 만들기] | 시청자 → 발표자 전환. 앱 안에서 생기는 유일한 유입 경로를 직접 연다 | 시청자 결과 화면의 "나도 만들기" |
| 로그인 전 데모(랜딩 미리보기를 직접 눌러 보기) | 가입 전에 첫 판정을 본다. 1~2단계 비용이 사라진다 | 로그인 전 데모. 조건은 "랜딩→로그인 이탈이 보이면"인데 방문자 분석도 제외라 7절 점검으로 판단해야 한다 |
| 토론 형식 템플릿(1:1, 2:2 등) | 주 고객(토론 수업 교사)의 3단계 입력 시간이 줄어든다 | 템플릿 |
| 타이머 복제 | 여러 조·행사 준비가 빨라진다 | 타이머 복제 |
