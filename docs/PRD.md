# PRD: Podium Timer

## 목표
발표·토론에서 **남은 시간이 아니라, 정해진 구간 계획 대비 지금 빠른지 느린지**를 보여주는 페이스 타이머. 혼자 쓰면 1인 발표 타이머, 링크로 공유하면 여러 명이 같은 타이머를 보는 토론 타이머가 된다. 끝나면 구간별 계획 대비 실제 시간 리포트를 남긴다.

MVP는 **프로토타입 수준**이다. 핵심 가치를 검증하는 데 필요한 만큼만 만들고, 단순하게 갈 수 있는 곳은 단순하게 간다.

## 용어

| 용어 | 뜻 |
|---|---|
| 룸 | 구간 목록, 발언자 이름표, 허용 오차·알림 설정, 공유 링크를 묶은 저장 단위. 사용자가 만들고 저장한다 |
| 구간 | 룸 안의 시간 블록 하나 (이름, 계획 시간, 발언자, 알림 시점, 허용 오차) |
| 방장 | 룸을 만든 사람. Google 로그인. 타이머를 조작하는 유일한 사람 |
| 참여자 | 공유 링크나 QR로 들어와 닉네임만 입력하는 사람. 로그인 없음. 보기 전용 |
| 세션 | 룸을 한 번 [시작]해서 종료할 때까지의 실행 한 번. 리포트의 단위 |
| 모드 | 발표 / 토론. 룸을 만들 때 고른다. 토론일 때만 구간에 발언자를 지정한다 |

### 가설과 확인 방법

별도 분석 도구 없이 DB 기록으로 확인한다.

| 가설 | 맞다면 보이는 신호 | 확인할 데이터 |
|---|---|---|
| H1. '몇 초 앞/뒤'가 남은 시간보다 발표자의 행동을 더 잘 바꾼다 | 같은 룸에서 회차가 거듭될수록 최종 차이가 줄어듦 | `sessions` 회차별 최종 누적 차이 |
| H2. 리포트가 반복 연습을 만든다 | 한 룸을 여러 번 실행 | 룸당 세션 수 |
| H3. 교실에서는 학생 폰보다 교실 TV 하나로 본다 | 토론 룸의 최대 참여자 수가 0~2명 | `sessions.peak_guests` |
| H4. 참여자로 써본 사람이 새 방장이 된다 | 리포트 화면의 "나도 만들기"를 거친 가입이 있음 | `profiles.signup_ref` |
| H5. 30일권은 행사 직전에 산다 | 결제 직후 7일 안에 세션이 몰림 | `passes.paid_at` vs `sessions.started_at` |
| H6. 무료 한도는 개인 발표와 1:1 수업에 충분하다 | 결제가 주로 인원 초과에서 일어남 | `passes.purchase_source` |
| H7. 로그인 전에 가치를 못 느끼면 떠난다 | — | MVP에서는 측정하지 않음 |

## 핵심 기능
1. **룸 만들기·편집** — 모드(발표/토론) 선택, 구간 추가(이름·시간·발언자·알림 시점·허용 오차), 추천 템플릿 3개, 계정에 저장.
2. **페이스 타이머** — 방장이 수동으로 구간을 넘기고, 계획 대비 누적 차이·상태 색·타임라인 바·남은 시간을 보여준다. 알림, 키보드·리모컨·화면 탭 조작.
3. **공유** — 링크·QR로 참여자가 닉네임만 입력하고 입장해 같은 타이머를 실시간으로 본다. 플랜별 동시 접속 한도.
4. **결과 리포트** — 종료 직후 방장과 참여자에게 구간별 계획 vs 실제, 페이스 그래프. 방장은 지난 기록 목록에서 다시 본다.
5. **로그인** — Google 로그인 (방장만).
6. **결제** — Polar 30일 이용권 (MVP는 sandbox).
7. **배포** — Vercel. mock 모드로 먼저 배포한 뒤 실제 서비스를 연동한다.

## 정책

### 플랜

| | 무료 | 프로 |
|---|---|---|
| 룸 수 | 3개 | 무제한 |
| 룸 1개당 구간 수 | 6개 | 50개 |
| 동시 접속 (방장 포함, 방장은 기기 수와 상관없이 1명) | 3명 | 10명 |

- 한도는 **새로 만들 때와 저장할 때만** 검사한다. 프로가 만료돼도 데이터는 그대로이고, 이미 만든 룸도 실행할 수 있다. 다만 새 룸 만들기, 구간 7개 이상 저장, 4번째 참여자 입장에는 다시 무료 한도가 적용된다.
- 진행 중인 세션은 [시작]할 때의 인원 한도를 끝까지 유지한다.
- 한도를 넘는 순간(룸 4개째, 구간 7개째, 4번째 참여자)이 결제 안내로 이어지는 지점이다.

### 결제
- 상품: **자동 갱신 없는 30일 이용권 하나**. 계정 전체에 30일 동안 프로 적용.
- 결제 서비스: Polar (판매 대행). MVP는 **Polar sandbox**에서 결제 → 프로 반영 → 원래 화면 복귀 → 만료까지 전체 흐름이 동작하면 완료.
- 이미 프로인데 또 사면 **만료일에 30일을 더한다** (연장).
- 환불은 Polar 대시보드에서 처리한다. **부분 환불이든 전액 환불이든 환불된 30일권은 무효**가 되고, 남은 구매 기록으로 만료일을 다시 계산한다. 연장 구매가 있으면 뒤 이용권의 시작이 앞당겨질 수 있다.
- 재계산된 만료일이 이미 지났으면 즉시 무료로 전환한다. 진행 중 세션의 인원 한도는 그대로 유지한다. 앱이 자동으로 환불하지 않는다.
- 가격: 미정. Polar 대시보드에서 정하고 코드에는 넣지 않는다.

### 로그인과 공유
- 방장: Google 로그인만. 룸 생성에 필수. 가입은 만 14세 이상.
- 참여자: 로그인 없음. 닉네임(기기에 저장)만 입력하고 입장 (Zoom 참가자 방식).
- 공유: 링크만 있으면 누구나. 공유 토큰은 추측할 수 없는 무작위 값. 진행 화면에서 링크 복사와 QR 코드를 제공한다.
- 장난·유출 대응: **링크 다시 만들기**. 링크를 바꾸면 기존 참여자는 모두 끊기고 새 링크로 다시 들어와야 한다. CAPTCHA, 개별 내보내기, 입장 횟수 제한은 하지 않는다.

### 타이머 동작
- 구간은 **방장이 수동으로** 넘긴다. 계획 시간을 넘겨도 자동으로 넘어가지 않고 초과 시간을 계속 센다.
- 조작: [시작] · [다음] · [일시정지/재개] · [취소](방금 누른 '다음' 되돌리기) · [지금 종료](중도 종료).
- 마지막 구간의 [다음]은 "한 번 더 누르면 종료"를 3초간 띄우고, 다시 누르면 종료한다 (확인창 대신이라 발표 리모컨으로도 가능).
- 일시정지한 시간은 페이스 계산에서 뺀다.
- 알림: 구간 종료 N초 전과 종료 시점에 **화면 테두리 깜빡임(기본) + 소리 + 진동**. iPhone은 웹 진동을 지원하지 않고 무음 모드에서는 소리가 안 날 수 있어서 깜빡임을 기본으로 둔다. 참여자 화면에서도 울리고 각자 끌 수 있다.
- 화면 꺼짐 방지(Wake Lock)는 진행 화면에서 자동으로 켠다.
- 키보드: `Space`·`→`·`PageDown` = 다음, `←`·`PageUp` = 취소, `P` = 일시정지/재개. 발표 리모컨과 호환.
- **터치 기기(폰·태블릿)에서는 타이머 화면 아무 곳이나 탭하면 [다음].**
  - 버튼(일시정지·취소·지금 종료·공유) 위를 누르면 그 버튼만 동작한다.
  - 손가락이 움직인 스와이프는 탭으로 보지 않는다.
  - 0.5초 안의 두 번째 탭은 무시한다. 마지막 구간에서는 탭 → "한 번 더 누르면 종료" → 다시 탭으로 종료한다.
  - 두 번 탭 확대와 텍스트 선택은 막는다.
  - 방장 화면에서만 동작하고, 참여자 화면은 탭해도 아무 일도 없다.
- 전체화면 버튼: 지원하는 기기에서만 보인다 (iPhone은 미지원이라 숨김).

### 페이스 표시와 계산

| 표시 | 내용 |
|---|---|
| 차이 시간 숫자 (메인) | 전체 계획 대비 누적 차이. "+0:42 느림" / "-0:20 빠름" |
| 상태 색 | 정상 초록 / 빠름 파랑 / 느림 빨강. 색 옆에 글자도 함께 표시 |
| 타임라인 바 | 전체 구간 막대 위에 '계획상 지금 위치'와 '실제 위치' 두 마커 |
| 남은 시간 (보조) | 현재 구간 남은 시간(넘으면 초과 시간), 전체 남은 시간 |
| 발언자별 (토론만) | 발언자(팀)마다 계획 대비 차이 + 전체 |

- **진행 중 누적 차이**: `max(현재 구간 시작까지의 실제 활성 경과 − 그 구간의 계획상 시작 시점, 실제 활성 경과 − 그 구간의 계획상 종료 시점)`. 활성 경과는 일시정지를 뺀 시간이다. 즉 "현재 구간을 계획한 시간만큼 쓴다고 가정했을 때 전체가 얼마나 늦어질지". 구간 안에서는 숫자가 흔들리지 않고, 계획 시간을 넘긴 순간부터 실시간으로 늘어난다.
- **종료 시 누적 차이**
  - 정상 종료(`completed`): `실제 활성 경과 − 전체 계획 시간`. 마지막 구간을 일찍 끝낸 시간도 최종 차이에 반영된다.
  - 중도 종료(`stopped`): **종료 순간의 진행 중 누적 차이**를 그대로 최종값으로 쓴다. 종료 직전 화면에 보이던 숫자와 같다.
- **상태 판정**: |누적 차이| ≤ 허용 오차 → 정상. 그보다 늦으면 느림, 빠르면 빠름. 허용 오차는 현재 구간의 유효 값(아래 '기본값'의 계산)을 쓴다.
- **발언자별 차이**: 그 발언자의 끝난 구간들의 (실제 − 계획) 합 + 지금 그 발언자의 구간이 계획을 넘겼다면 넘긴 만큼.

### 결과 리포트
- 내용: **구간별 계획 vs 실제 시간 표**, 전체 차이, **페이스 변화 그래프**(누적 차이가 시간에 따라 어떻게 변했는지).
  - 끝까지 진행한 구간: 실제 시간과 차이(`actualMs − plannedMs`)를 표시한다.
  - 중도 종료한 구간: "중단"으로 표시하고 실제 시간만 보여준다 (차이는 표시하지 않음).
  - 그 뒤 구간: "미진행"으로 표시한다 (실제 시간·차이 없음).
  - 전체 차이는 위 '종료 시 누적 차이'다. 전체 계획 시간, 진행한 구간의 계획 시간, 실제 활성 시간을 함께 표시해 중도 종료를 구분한다. 그래프의 마지막 점은 최종 누적 차이다.
- 진행 중 세션을 보던 참여자는 해당 세션 종료 시 리포트로 바뀐다. 잠깐 끊겼다가 돌아온 참여자도 같은 세션의 최종 기록을 조회해 복구한다. 종료 뒤 처음 들어온 참여자는 대기실로 간다.
- 참여자 화면은 진행 중에 관찰한 `observedSessionId`를 공유 토큰별 `sessionStorage`에 보관한다. 상태 조회에 이 ID를 보내 종료된 세션의 스냅샷·최종 이벤트를 받는다. 새로 입장한 탭은 이 ID가 없으므로 지난 리포트를 자동으로 보여주지 않는다. 이는 화면 전환 규칙이며 서버가 종료 순간의 참석 여부를 인증하는 방식은 아니다.
- 새 진행 중 세션이 있으면 그 세션을 우선 표시하고 `observedSessionId`를 갱신한다. 기존 리포트는 새 세션이 시작될 때까지 유지하며, 토큰이 바뀌면 보관한 ID와 화면 데이터를 지운다.
- 방장은 룸마다 **지난 기록 목록**(회차별 날짜, 전체 차이)에서 리포트를 다시 보고, 망친 기록은 삭제할 수 있다. 기록은 플랜과 상관없이 모두 보관한다.

### 입력 범위

화면과 서버 양쪽에서 같은 스키마로 검사한다.

| 항목 | 범위 |
|---|---|
| 룸 제목 | 1~60자 |
| 구간 이름 | 1~40자 |
| 구간 시간 | 5초 ~ 3시간 |
| 구간에 직접 지정한 허용 오차, 알림 시점 | 0 ~ 그 구간 시간 |
| 룸 기본 허용 오차, 알림 시점 | 0 ~ 3시간. 구간에 상속할 때 구간 시간 이하로 제한 |
| 발언자 이름표 | 1~10개, 각 1~20자 (토론 모드만) |
| 닉네임 | 1~20자, 앞뒤 공백과 보이지 않는 제어 문자 제거, 중복 허용(뒤에 번호) |
| 구간 0개인 룸 | 시작 불가 |

### 기본값과 템플릿
- 룸 기본 허용 오차: **15초**. 기본 알림 시점: 구간 종료 **30초 전**. (초안, 조정 가능)
- 구간에 개별 값이 없으면 `min(룸 기본값, 구간 시간)`을 유효 값으로 쓴다. 개별 값을 직접 지정했다면 범위를 넘는 입력은 오류로 처리한다. 화면·서버·페이스 엔진 모두 같은 유효 값 계산 함수를 사용한다. 예: 5초 구간은 상속 시 허용 오차 5초, 알림 5초 전이다.
- 알림 시점 `0`은 종료 시점 알림과 합쳐 한 번만 울린다. 알림 시점이 구간 시간과 같으면 구간 진입 시 한 번 울린다. 알림은 `(sessionId, 구간 진입 eventId, 알림 종류)`별로 중복을 막고, 뒤늦은 입장·화면 복귀 시 이미 지난 알림은 재생하지 않는다. 취소 후 다시 진입한 구간은 새 진입으로 취급한다.
- 템플릿은 코드에 고정한다 (DB에 넣지 않음). 시간은 초안이다.

| 템플릿 | 모드 | 구간 |
|---|---|---|
| 5분 피칭 | 발표 | 문제 1:00 · 해결책 1:30 · 데모 1:30 · 마무리 1:00 |
| 15분 발표 | 발표 | 도입 2:00 · 본론 9:00 · 결론 2:00 · Q&A 2:00 |
| 찬반 토론 | 토론 | 찬성 입론 3:00 · 반대 입론 3:00 · 찬성 반론 2:00 · 반대 반론 2:00 · 찬성 최종변론 2:00 · 반대 최종변론 2:00 (6구간, 무료 한도 안) |

### 흐름 F. 세션 상태

```
 대기 ──[시작]──→ 진행 중 ──[마지막 구간에서 다음 ×2]──→ 종료 → 리포트 저장
                   │  ↑
       [일시정지]  ↓  │  [재개]
                 일시정지

 진행 중 안에서: [다음] 다음 구간으로 · [취소] 방금 누른 다음 되돌리기
 진행 중 · 일시정지 ──[지금 종료]──→ 종료 (종료한 구간 "중단", 남은 구간 "미진행")
 종료 ──[다시 실행]──→ 대기 (같은 링크 · 세션은 [시작]할 때 새로 생성)
 종료하지 않고 닫음 → 다음에 룸을 열면 "이어서 하기 / 지금 종료" 선택
```

- '대기'는 진행 중인 세션이 없는 룸 상태다. 세션은 [시작]을 누를 때 만들고, 그때 구간 목록과 인원 한도를 세션에 복사한다. 그래서 대기 중에 고친 구간이 반영되고, 나중에 룸을 고쳐도 지난 리포트는 그대로 남는다.

## 예외 상황

| 상황 | 앱 동작 |
|---|---|
| 방장 폰 화면이 꺼지거나 다른 앱으로 전환 | 화면 꺼짐 방지가 기본. 돌아오면 다시 계산해서 정확한 시간 표시, 화면 꺼짐 방지 다시 켬 |
| 방장 Wi-Fi가 잠깐 끊김 | 방장 화면에는 바로 반영. 서버 전송은 자동 재시도. 오래 끊기면 "연결 안 됨 · 다시 시도" 표시 |
| 저장은 성공했지만 응답만 유실 | 같은 eventId로 재전송하면 기존 성공 결과 반환. 후속 이벤트는 순서대로 전송 |
| DB 저장 뒤 Broadcast 실패·신호 누락 | 연결이 살아 있어도 10초 간격 상태 재조회로 복구. 화면 복귀·재접속 시 즉시 재조회 |
| 방장이 기기를 바꿈 | 같은 계정으로 룸을 열면 진행 중인 세션을 이어서 조작 |
| 방장이 두 기기를 동시에 사용 (노트북은 TV, 폰은 리모컨) | 둘 다 조작 가능. 동시에 누르면 하나만 반영되고, 다른 기기는 서버 상태로 맞춘 뒤 "다른 기기의 기록으로 맞췄어요" 안내 |
| 같은 버튼을 빠르게 두 번 누름, 버튼에 초점이 있는 채로 스페이스 | 0.5초 안의 두 번째 '다음'은 무시. 단축키는 버튼 기본 동작을 막고, 글자 입력 칸에서는 꺼짐 |
| 폰을 단상에 놓거나 쥐다가 화면을 건드려 구간이 넘어감 | [취소]로 되돌림. 손가락이 움직인 스와이프는 무시 |
| 마지막 구간에서 실수로 [다음] | "한 번 더 누르면 종료"가 3초 뒤 사라지고 그대로 진행 |
| 종료하지 않고 닫음 | 다음에 룸을 열면 "이어서 하기 / 지금 종료" 선택. 종료하기 전까지 룸 편집은 잠김 |
| 진행 중 룸 편집 시도 | "진행 중에는 수정할 수 없어요" |
| 인원 가득 | 입장 거부 + 방장 화면에 알림 |
| 참여자가 탭을 닫거나 화면을 오래 끔 | 접속자 목록에서 빠지고 자리가 비워짐. 돌아오면 자동 재접속 (그사이 자리가 찼으면 인원 가득) |
| 링크 유출·장난 | 방장이 링크 다시 만들기 → 전원 끊김 → 새 링크로 다시 입장 |
| 브라우저가 소리 자동 재생을 막음 | [입장]·[시작]을 누를 때 소리를 켬. 꺼져 있으면 아이콘으로 표시 |
| 화면이 꺼지거나 다른 탭에 있어서 알림이 늦음 | 돌아왔을 때 다시 계산해서 화면을 맞춤 (알림은 화면이 켜져 있을 때만 보장) |
| 결제 웹훅이 늦게 옴 | 완료 페이지가 몇 초 확인 후 "반영이 늦어지고 있어요" 안내 |
| 결제 웹훅 중복·역순·동시 도착 | 주문 ID 기준으로 병합하고 매번 전체 구매 기록으로 만료일을 다시 계산. 동시 처리로 어긋나면 결제 완료·계정 화면에서 다시 계산할 때 복구 |
| 환불로 만료일이 이미 지남 | 무료로 전환. 데이터 보존, 진행 중 세션의 기존 인원 한도 유지 |
| 진행 중에 프로 만료 | 그 세션은 시작할 때의 인원 한도 유지 |
