# PRD: Podium Timer

## 목표
발표·토론을 구간으로 나눠 두고, 발표자가 구간을 넘길 때마다 **그 구간이 계획보다 빨랐는지 늦었는지** 바로 보여주는 페이스 타이머. 남은 시간만 보여주는 타이머와 달리 "어느 구간에서 시간이 부족하고 어디가 넉넉한지"를 알려준다. 혼자 쓰면 1인 발표 타이머, 링크로 공유하면 여러 명이 같은 타이머를 보는 토론 타이머가 된다. 끝나면 구간별 계획 대비 실제 시간 표를 남기고, 기록이 쌓이면 구간별 평균을 보여준다.

MVP는 **프로토타입 수준**이다. 로그인 → 타이머 → 공유 → 결제(테스트 모드) → 배포까지 실제로 동작하는 것이 목표이고, 단순하게 갈 수 있는 곳은 단순하게 간다. 실제 결제와 운영 수준의 견고함은 범위 밖이다.

## 용어

| 용어 | 뜻 |
|---|---|
| 타이머 | 이름 + 구간 목록. 사용자가 만들고 계정에 저장한다 |
| 구간 | 타이머 안의 시간 블록 하나(이름, 계획 시간). 토론에서는 발언 하나가 구간 하나다(예: "찬성 입론 3:00") |
| 발표자 | 타이머를 만들고 조작하는 사람. Google 로그인. 토론에서는 사회자·타임키퍼가 발표자 역할을 한다 |
| 시청자 | 공유 링크로 들어와 닉네임만 입력하는 사람. 로그인 없음. 보기 전용 |
| 발표 | 타이머를 [시작]해서 끝낼 때까지의 실행 한 번 |
| 기록 | 마지막 구간까지 끝낸 발표의 구간별 계획·실제 시간 |
| 공유 링크 | 발표 한 번을 시청자에게 보여주는 링크. 시작 전에 만든다 |

## 사용자

| 사용자 | 상황 | 주 기기 | 예상 플랜 | 원하는 것 |
|---|---|---|---|---|
| 학생 발표자 | 수업·조별·졸업 발표. 며칠 전부터 혼자 연습 | 폰, 노트북 | 무료 | 시간 안에 끝내기, 어느 구간에서 늦어지는지 알기 |
| **토론 수업 교사** (주 고객 가설) | 매주 토론 수업에서 사회자 겸 심사로 시간 관리 | 노트북, 폰 | 1:1은 무료, 팀 토론은 30일권 | 준비는 최소로, 학생들이 같은 타이머를 보기 |
| 비전문 강연자·직장인 | 사내 발표, 세미나, 짧은 강연 | 노트북, 폰 | 평소 무료, 행사 때 30일권 | 연습하면서 구간별 시간 감 잡기 |
| 행사·토론대회 운영자 | 2:2·3:3 토론, 심사위원·스태프가 함께 봄 | 노트북 | 행사 직전 30일권 | 10명이 같은 화면을 안정적으로 보기 |
| 시청자 (토론자·심사·청중) | 링크를 받음, 계정 없음 | 폰 | — | 바로 들어가서 지금 구간 시간 보기 |

### 시나리오

| # | 시나리오 | 발표자 | 시청자 | 접속 인원 | 플랜 |
|---|---|---|---|---|---|
| S1 | 혼자 리허설 | 발표자 | 없음 | 1 | 무료 |
| S2 | 1인 발표 실전 | 발표자 | 없음 | 1 | 무료 |
| S3 | 진행자가 다른 사람의 발표 시간 관리 | 진행자 | 실제 발표하는 사람(단상 태블릿) | 2 | 무료 |
| S4 | 토론 수업 1:1 | 교사 | 학생 2명 | 3 | 무료 |
| S5 | 토론 수업 2:2, 여러 조 연속 | 교사 | 학생 4명 | 5 | 30일권 |
| S6 | 토론대회·행사 | 운영자 | 토론자·심사·스태프 | 최대 10 | 30일권 |
| S7 | 30일권 만료 후 다시 접속 | 이전 30일권 사용자 | — | — | 무료로 전환 |

## 핵심 기능
1. **타이머 만들기·편집** — 구간 추가(이름·시간), 순서 변경, 계정에 저장.
2. **페이스 타이머** — 발표자가 수동으로 구간을 넘기고, 넘길 때마다 그 구간의 계획 대비 차이를 보여준다. 현재 구간 남은 시간, 타임라인 바, 전체 남은 시간. 화면 탭·스페이스바 조작.
3. **공유** — 시작 전에 만든 링크로 시청자가 닉네임만 입력하고 들어와 같은 타이머를 실시간으로 본다. 플랜별 동시 접속 한도.
4. **결과와 기록** — 종료 직후 발표자와 시청자에게 구간별 계획 / 실제 / 차이 표. 발표자는 기록 목록과 구간별 평균을 다시 본다.
5. **로그인** — Google 로그인 (발표자만).
6. **결제** — Polar 30일권 (MVP는 sandbox).
7. **배포** — Vercel. mock 모드로 먼저 배포한 뒤 실제 서비스를 연동한다.

## 정책

### 플랜

| | 무료 | 30일권 |
|---|---|---|
| 타이머 수 | 3개 | 무제한 |
| 타이머 1개당 구간 수 | 10개 | 30개 |
| 공유 동시 접속 (발표자 포함, 발표자는 기기 수와 상관없이 1명) | 3명 | 10명 |
| 공유 링크 만들기 | 제한 없음 | 제한 없음 |
| 기록·평균 | 제한 없음 | 제한 없음 |

- 한도는 **새로 만들 때와 저장할 때만** 검사한다. 30일권이 만료돼도 데이터는 그대로이고, 이미 만든 타이머도 실행할 수 있다. 다만 새 타이머 만들기, 구간 11개 이상 저장, 4번째 접속에는 다시 무료 한도가 적용된다.
- 공유의 인원 한도는 [시작]할 때의 플랜으로 정하고, 그 발표가 끝날 때까지 유지한다.
- 한도를 넘는 순간(타이머 4개째, 구간 11개째, 4번째 접속)이 결제 안내로 이어지는 지점이다. "무료 한도(타이머 3개)에 도달했어요" 같은 안내와 "30일권 보기" 버튼을 보여준다. 버튼을 미리 숨기거나 비활성화하지 않는다.

### 결제
- 상품: **자동 갱신 없는 30일권 하나**, $3.99. 계정 전체에 30일 동안 적용.
- 결제 서비스: Polar (판매 대행). MVP는 **Polar sandbox**에서 결제 → 30일권 반영 → 원래 화면 복귀 → 만료까지 전체 흐름이 동작하면 완료.
- 화면은 한국어, 가격은 USD로 표시하고 원화 환산은 표시하지 않는다.
- 이미 30일권이 있는데 또 사면 **만료일에 30일을 더한다** (연장).
- 환불은 Polar 대시보드에서 수동으로 처리한다. 앱은 이용권을 자동으로 회수하지 않는다.
- 결제 내역 화면은 없다. 영수증은 Polar가 이메일로 보낸다.

### 로그인과 공유
- 발표자: Google 로그인만. 타이머 생성에 필수. 가입은 만 14세 이상.
- 시청자: 로그인 없음. 닉네임(기기에 저장)만 입력하고 입장 (Zoom 참가자 방식).
- 공유 링크: 발표자가 **시작 전에만** 만든다. 링크 하나는 발표 한 번 전용이고, 다음 발표는 새 링크를 만든다. 만들기 횟수 제한은 없다. 링크 코드는 추측할 수 없는 무작위 값이다. 링크 복사로 보낸다(QR 없음).
- 링크를 만들 때 타이머 이름과 구간을 대기실용으로 넣고, [시작]할 때 발표자가 실제로 쓰는 구간과 그 순간의 인원 한도로 덮어쓴다.
- 장난·유출 대응 기능은 없다. 링크를 다시 만들거나 한 명만 내보낼 수 없고, 그 발표가 끝나면 링크도 끝난다.

### 타이머 동작
- 구간은 **발표자가 수동으로** 넘긴다. 계획 시간을 넘겨도 자동으로 넘어가지 않고 초과 시간을 계속 센다.
- 조작: [시작] · [다음] · [되돌리기](방금 누른 '다음' 취소) · [중단].
- 마지막 구간의 [다음]은 "한 번 더 누르면 종료"를 3초간 띄우고, 다시 누르면 종료한다 (확인창 대신이라 스페이스바로도 가능).
- [중단]은 확인 창을 거쳐 발표를 끝낸다. 중단한 발표는 기록하지 않는다.
- 일시정지는 없다.
- 구간 시간이 다 되면 숫자가 빨간색 마이너스로 바뀐다. 소리·진동·미리 경고는 없다.
- 화면 꺼짐 방지(Wake Lock)는 진행 화면에서 자동으로 켠다.
- 키보드: `Space` = 다음. 글자 입력 칸에서는 꺼진다.
- **터치 기기(폰·태블릿)에서는 타이머 화면 아무 곳이나 탭하면 [다음].**
  - 상단 바(되돌리기·중단 버튼, 진행·접속 표시)는 탭해도 [다음]으로 넘어가지 않는다.
  - 손가락이 움직인 스와이프는 탭으로 보지 않는다.
  - 0.5초 안의 두 번째 탭은 무시한다. 마지막 구간에서는 탭 → "한 번 더 누르면 종료" → 다시 탭으로 종료한다.
  - 두 번 탭 확대와 텍스트 선택은 막는다.
  - 발표자 화면에서만 동작하고, 시청자 화면은 탭해도 아무 일도 없다.
- 실행 화면을 다시 열면(새로고침·앱 전환·닫았다 다시 엶) 진행 중이던 발표를 그대로 이어간다. 시작한 지 12시간이 지난 진행 상태는 버리고 대기로 돌아간다. 끝났거나 중단한 발표는 다시 열면 대기로 돌아간다(결과는 기록 화면에서 본다).
- 같은 타이머를 여러 기기에서 동시에 실행하는 것은 막지 않는다. 각 기기가 따로 실행하고, 발표 도중 다른 기기로 옮겨 이어가지는 못한다.

### 페이스 표시와 계산

| 표시 | 내용 |
|---|---|
| 현재 구간 남은 시간 (메인) | 계획 − 현재 구간 경과. 0을 지나면 빨간 마이너스로 늘어난다 |
| 타임라인 바 | 구간별 블록(계획 시간 비율) 위에 진행 위치 마커 하나 |
| 전체 남은 시간 | 계획 합계 − 발표 시작 후 경과. 0을 지나면 마이너스로 늘어난다 |
| 진행 | "3 / 7"과 현재 구간 이름, 다음 구간 이름 |
| 직전 구간 결과 | "0:12 늦음" / "0:08 빠름" / "정시" (색과 글자 함께) |

- **구간 실제 시간**: 그 구간이 시작된 뒤 [다음]을 누를 때까지 걸린 시간.
- **구간 차이** = 실제 − 계획. 양수면 늦음, 음수면 빠름. 화면에 보이는 대로 초 단위로 반올림한 절댓값이 1초 이하면 정시다. 그래서 "0:01 늦음"·"0:01 빠름"은 나오지 않는다.
- 진행 화면의 판정은 구간별로만 한다. 진행 중에는 누적 차이를 계산하지도 표시하지도 않는다.
- **기록 전체 차이** = 기록의 실제 합계 − 계획 합계. 기록 목록에서만 기록마다 보여주고, 판정 규칙(반올림해 1초 이하면 정시)과 표기("0:13 늦음")는 구간 차이와 같다.
- **진행 위치** = 현재 구간의 계획상 시작 지점 + min(현재 구간 경과, 현재 구간 계획 시간). 현재 구간을 넘겨 쓰면 그 블록 끝에 멈춘다. 계획 대비 위치는 표시하지 않는다.

### 결과와 기록
- 종료하면 발표자 화면과 시청자 화면 모두 구간별 **계획 / 실제 / 차이** 표로 바뀐다. 잠깐 끊겼다 돌아온 시청자, 종료 뒤 링크를 연 시청자도 인원 한도와 상관없이 같은 결과를 본다.
- 중단하면 시청자 화면은 "발표가 중단되었어요"로 바뀐다.
- 마지막 구간까지 끝낸 발표만 자동으로 기록한다. 저장 내용은 시작 일시, 구간별 이름·계획 시간·실제 시간이다. [시작]할 때 복사한 구간을 쓰므로 타이머를 고쳐도 옛 기록은 바뀌지 않는다.
- 결과 화면의 [다시 하기]로 같은 타이머를 바로 다시 시작할 수 있다(리허설 반복). 공유 중이었다면 새 발표는 새 링크가 필요하다.
- 발표자는 타이머마다 **기록 목록**(최신순, 시작 일시, 실제·계획 합계, 기록 전체 차이)을 보고, 기록을 누르면 그 자리에서 결과 표가 펼쳐진다. 망친 기록은 펼친 결과 아래에서 하나씩 삭제할 수 있다(확인 창).
- **평균**: 기록이 2개 이상일 때 목록 위에 보여준다. 현재 타이머와 구간 구성(구간 개수와 이름 순서)이 같은 기록만 넣는다.
  - 표: 구간별 계획 / 평균 실제 / 평균 차이
  - 그래프: 구간별 평균 차이 막대그래프(늦음은 오른쪽 빨강, 빠름은 왼쪽 파랑)
- 기록·평균은 플랜과 상관없이 모두 보관하고 보여준다.

### 입력 범위

화면과 서버 양쪽에서 같은 스키마로 검사한다.

| 항목 | 범위 |
|---|---|
| 타이머 이름 | 1~60자 |
| 구간 이름 | 1~40자 |
| 구간 시간 | 5초 ~ 3시간. `m:ss` 형식 한 칸으로 입력 (예: `3:00`, `125:00`). 숫자만 적으면 분으로 읽는다 (`3` → `3:00`) |
| 닉네임 | 1~20자, 앞뒤 공백과 보이지 않는 제어 문자 제거, 중복 허용 |
| 구간 0개인 타이머 | 시작 불가 |

│  │                       위: 플랜("무료" / "30일권 · 11월 25일까지") · [30일권 구매] · 로그아웃
│  │                       무료는 새 타이머 버튼에 "2/3" 한도 표시
│  ├─ /timers/new          타이머 만들기
│  ├─ /timers/[id]         타이머 편집: 이름 · 구간
│  ├─ /timers/[id]/run     진행: 시작 전(공유 링크 · 접속자) → 진행 → 결과
│  ├─ /timers/[id]/records 기록 목록 · 구간별 평균 표와 그래프 · 기록 삭제
│  ├─ /pricing             요금제: 무료/30일권 비교, $3.99
│  └─ /billing/success     결제 완료 → 30일권 반영 확인 → 원래 화면으로
│
├─ 공통
│  ├─ /terms               이용약관 (환불 규정 포함)
│  └─ /privacy             개인정보처리방침
│
└─ 시청자 (로그인 불필요)
   └─ /s/[code]            닉네임 입력 → 대기실 → 시청 → 결과
```

모든 화면 하단에 개인정보처리방침·이용약관 링크와 문의 이메일을 둔다. 회원 탈퇴는 이 이메일로 요청받는다. 사업자 정보는 표시하지 않는다(사업자 아님).

   │   ↓

③ 실전 (단상 위 폰 또는 노트북)
   발표 직전 타이머 열기 → [시작] → 화면 꺼짐 방지 자동 켜짐
   │
   ├─ 구간이 끝남 → 화면 아무 곳이나 탭(폰) · Space(노트북) → 다음 구간
   ├─ 직전 구간이 늦음 → 빨강 "0:12 늦음" → 다음 구간을 줄여 말함
   ├─ 직전 구간이 빠름 → 파랑 "0:08 빠름" → 예시를 하나 더 들거나 천천히
   ├─ 현재 구간 시간이 다 됨 → 숫자가 빨간 마이너스로 바뀌고 계속 셈
   ├─ 실수로 [다음] → [되돌리기] → 직전 구간으로
   ├─ 앱 전환·새로고침 → 돌아오면 그대로 이어서
   ├─ 일찍 끝내야 함 → [중단] → 확인 → 기록하지 않음
   └─ 마지막 구간에서 [다음] → "한 번 더 누르면 종료"(3초) → 종료 → 결과 표

   변형 (S3): 진행자가 발표자로 조작하고, 실제 발표하는 사람은 단상 태블릿의 시청자 화면으로 봄

### 흐름 C. 토론 수업 (S4, S5)

```
[수업 전]
 교사 │ 타이머 만들기 → 발언 순서대로 구간 입력(찬성 입론 3:00 · 반대 입론 3:00 · …) → 저장

[입장]
 교사 │ 진행 화면(시작 전) → [공유 링크 만들기] → 링크 복사 → 반 단톡방에 보냄
 학생 │ 링크 열기 → 닉네임 입력 → 대기실 "발표자가 시작하면 자동으로 시작돼요"
 교사 │ 접속자 확인: 3/3명 (발표자 포함)
 학생 │ 4번째 학생 → "인원이 가득 찼어요"
 교사 │ "자리가 가득 찼어요 · 30일권은 10명까지" (결제로 이어지는 순간 ③)

[진행]
 교사 │ [시작] → 공유에 구간과 인원 한도 확정
 서버 │ 상태 저장 → "changed" 신호 → 학생 화면이 서버에서 다시 읽고 같은 기준 시각으로 카운트
 교사 │ [다음] 찬성 입론 끝 (노트북은 Space, 폰·태블릿은 화면 탭)
 모두 │ "반대 입론" 화면 · 직전 구간 "0:15 늦음"

[종료]
 교사 │ 마지막 구간에서 [다음] → 한 번 더 [다음]
 모두 │ 결과 표로 전환 (잠깐 끊겼어도 다시 읽어서 복구)

[다음 조]
 교사 │ [다시 하기] → [공유 링크 만들기] → 새 링크를 다시 보냄
```

### 흐름 D. 시청자 입장

```
링크 열기
   │
   ├─[없는 링크] → "존재하지 않는 링크예요"
   └─[링크 있음] → 닉네임 입력(전에 쓴 닉네임 자동 채움) → [입장]
         │
         ├─[인원 가득] → "인원이 가득 찼어요 (3/3)" · 발표자 화면에도 알림
         ├─[대기 중]   → 대기실 → 발표자가 시작하면 자동 전환
         ├─[진행 중]   → 지금 상태 바로 표시 (서버 시각으로 맞춤)
         ├─[종료]      → 결과 표
         └─[중단]      → "발표가 중단되었어요"

   진행 중 새로고침 · 끊김 → 자동 재접속, 같은 닉네임 (그사이 자리가 찼으면 "인원 가득")
   발표자 연결이 끊겨도 → 타이머는 마지막 상태로 계속 흐름

### 흐름 E. 결제와 플랜

```
결제로 이어지는 순간
   ├─ ① 타이머 4개째 만들기 (무료 3개)
   ├─ ② 구간 11개째 저장 (무료 10개)
   ├─ ③ 공유 자리가 가득 참 (무료 3명) → 발표자 화면 안내
   └─ ④ 요금제 페이지 직접 방문
         │
         ▼
요금제 페이지 (복귀 경로 returnTo를 기억)
   └─[30일권 구매 $3.99] → Polar 결제 → 완료 → "30일권 반영 중" → 원래 하던 화면으로
                          └─ 이미 30일권이면: 지금 만료일 + 30일 (연장)
   ※ 결제 취소 · 실패 → 원래 화면으로, 변화 없음
   ※ 반영이 늦으면 → "결제는 완료됐어요, 반영이 늦어지고 있어요" → 타이머 목록
   ※ ③에서 결제하고 진행 화면으로 돌아오면 [시작] 때 10명으로 확정된다. 못 들어온 시청자는 링크를 다시 열면 된다

환불 (Polar 대시보드에서 수동 처리)
   └─ 30일권은 그대로 둔다 (자동 회수는 실서비스 전 보강)

만료
   └─ 무료로 전환 → 데이터는 그대로 · 이미 만든 타이머도 실행 가능
      새 타이머 만들기 · 구간 11개 이상 저장 · 4번째 접속 → 다시 무료 한도 적용
      (진행 중이던 발표의 공유는 시작할 때의 인원 한도로 끝까지)
```

### 흐름 F. 발표 상태

```
 대기 ──[시작]──→ 진행 중 ──[마지막 구간에서 다음 ×2]──→ 종료 → 결과 표 · 기록 저장
                   │
                   └──[중단 → 확인]──→ 중단 (기록 없음)

 진행 중 안에서: [다음] 다음 구간으로 · [되돌리기] 방금 누른 다음 취소
 종료 ──[다시 하기]──→ 대기 (공유 중이었다면 새 링크 필요)
 진행 중에 페이지가 다시 열림(새로고침 · 앱 전환 · 닫았다 다시 엶) → 그대로 이어서
 시작한 지 12시간이 지난 진행 상태 → 버리고 대기로 (기록 없음)
 종료·중단 뒤 페이지가 다시 열림 → 대기로 (결과는 기록 화면에서)
```

- 발표의 구간은 [시작]할 때 복사해 둔다. 진행 중에 타이머를 고쳐도 그 발표와 기록에는 반영되지 않는다.

## 예외 상황

| 상황 | 앱 동작 |
|---|---|
| 발표자 폰 화면이 꺼지거나 다른 앱으로 전환 | 화면 꺼짐 방지가 기본. 돌아오면 다시 계산해서 정확한 시간 표시, 화면 꺼짐 방지 다시 켬 |
| 발표자 Wi-Fi가 잠깐 끊김 | 발표자 화면에는 바로 반영. 공유 저장은 최신 상태로 자동 재시도하고, 그동안 "공유 연결 끊김"을 작게 표시 |
| 공유 저장 응답 유실·재전송·도착 순서 뒤집힘 | 서버는 지금보다 새 상태(`rev`가 큰 것)만 저장하고 나머지는 무시 |
| DB 저장 뒤 Broadcast 실패·신호 누락 | 연결이 살아 있어도 10초 간격 상태 재조회로 복구. 화면 복귀·재접속 시 즉시 재조회 |
| 발표자가 발표 도중 기기를 바꿈 | 이어서 조작할 수 없다. 새 기기에서는 새 발표로 시작한다(공유 중이었다면 새 링크) |
| 같은 타이머를 두 기기에서 실행 | 각자 따로 실행. 공유는 링크를 만든 기기만 보낸다 |
| 같은 버튼을 빠르게 두 번 누름, 버튼에 초점이 있는 채로 스페이스 | 0.5초 안의 두 번째 '다음'은 무시. 단축키는 버튼 기본 동작을 막고, 글자 입력 칸에서는 꺼짐 |
| 폰을 단상에 놓거나 쥐다가 화면을 건드려 구간이 넘어감 | [되돌리기]로 되돌림. 손가락이 움직인 스와이프는 무시 |
| 마지막 구간에서 실수로 [다음] | "한 번 더 누르면 종료"가 3초 뒤 사라지고 그대로 진행 |
| 종료하지 않고 닫음 | 다시 열면 그대로 이어서. 시작한 지 12시간이 지났으면 버리고 대기로 |
| 진행 중에 타이머 편집 | 저장된다. 진행 중인 발표는 [시작] 때의 구간으로 계속 간다 |
| 진행 중에 타이머 삭제 | 기록은 저장되지 않는다. 공유 링크는 "존재하지 않는 링크예요" |
| 인원 가득 | 입장 거부 + 발표자 화면에 "자리가 가득 찼어요" |
| 시청자가 탭을 닫거나 화면을 오래 끔 | 접속자 목록에서 빠지고 자리가 비워짐. 돌아오면 자동 재접속 (그사이 자리가 찼으면 인원 가득) |
| 링크 유출·장난 | 막는 기능은 없다. 그 발표가 끝나면 링크도 끝난다 |
| 결제 웹훅이 늦게 옴 | 결제 완료 화면이 몇 초 확인 후 "반영이 늦어지고 있어요" 안내 |
| 결제 웹훅 중복 | 주문 ID 기준으로 한 번만 반영 |
| 진행 중에 30일권 만료 | 그 발표의 공유는 시작할 때의 인원 한도 유지 |
